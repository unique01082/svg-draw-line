# `@baole-space/svg-motion` v0.1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the first verified public release of `@baole-space/svg-motion` and turn its GitHub repository into a professional package landing page.

**Architecture:** Keep runtime code and the public API unchanged. Add release-facing documentation and contract tests on the feature branch, fast-forward the verified commit to `master`, then bootstrap npm publication through the existing provenance-enabled GitHub Actions workflow. After the first package exists, replace the temporary npm credential with npm Trusted Publishing and remove the secret.

**Tech Stack:** TypeScript, Vite library mode, Vitest, Playwright, pnpm 10.33.0, GitHub Actions, GitHub CLI, npm CLI, npm Trusted Publishing.

## Global constraints

- Never print or persist the npm bootstrap token in files, command output, shell history, or release notes.
- Never force-push, rewrite published history, or move `v0.1.0` after npm accepts the version.
- Run the complete verification pipeline on the exact feature commit and again on the fast-forwarded `master` commit.
- Stop publication if GitHub Actions, npm identity, package ownership, tag/version equality, or registry verification is not exact.
- Preserve the package name, version, API, browser matrix, and nine-file tarball contract.
