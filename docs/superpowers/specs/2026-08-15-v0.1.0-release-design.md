# `@baole-space/svg-motion` v0.1.0 release design

## Goal

Publish the first public, provenance-backed release of
`@baole-space/svg-motion` from the exact verified source on `master`, while
turning the GitHub repository into a concise, professional landing page for
users and maintainers.

## Scope

The release includes both selected tracks:

1. Polish the public landing page and GitHub repository metadata.
2. Add maintainer documentation for contributing, security reports, and
   release history.
3. Integrate the completed feature branch into `master`, publish `v0.1.0`, and
   verify GitHub/npm state.
4. Bootstrap npm publishing with a short-lived credential, then migrate the
   package to GitHub OIDC Trusted Publishing and remove the bootstrap secret.

No runtime behavior, public API, version, package name, browser matrix, or
security policy changes are included.

## Repository presentation

The README remains the user-facing landing page. It will gain a compact hero,
CI/npm/license badges, a short capability table, and clearer navigation while
retaining the complete installation, Vanilla/React usage, security, browser,
accessibility, and release information already required by the v0.1 plan.

Maintainer material will move to dedicated files:

- `CONTRIBUTING.md`: Node/pnpm requirements, local setup, verification,
  contribution workflow, and pull-request expectations.
- `SECURITY.md`: supported version, private vulnerability-reporting path, and
  what information a useful report should contain.
- `CHANGELOG.md`: Keep a Changelog-style `0.1.0` entry describing the public
  API, security pipeline, motion presets, React adapter, and verified release
  matrix.

GitHub metadata will use a concise package description, topics related to SVG,
animation, TypeScript, WAAPI, and React, and no longer link to the outdated
Vite prototype. After npm publication, the repository homepage will point to
the package page.

## Integration and release sequence

1. Make and commit documentation/repository-polish changes on
   `codex/svg-motion-v0.1`.
2. Run the complete `pnpm verify` pipeline and production dependency audit.
3. Fast-forward local `master` to the verified feature commit and repeat the
   complete verification on the merged checkout.
4. Push `master`; confirm CI succeeds before tagging.
5. Create a short-lived granular npm automation credential through the signed
   in npm account and store it only as the repository `NPM_TOKEN` secret.
6. Create and push annotated tag `v0.1.0`. The tag workflow must verify that
   the tag equals `package.json`, run all gates, and publish with public access
   and provenance.
7. Confirm the npm package contents, version, public access, provenance, core
   entry, and React entry from the registry.
8. Create a non-draft GitHub Release for `v0.1.0` with concise release notes.
9. Configure npm Trusted Publisher for
   `unique01082/svg-draw-line/.github/workflows/publish.yml`, allowing
   `npm publish` only. Remove the GitHub `NPM_TOKEN` secret and revoke the
   bootstrap credential.
10. Point GitHub's homepage metadata to the npm package and verify the public
    repository, release, tag, Actions run, and npm listing.

If the publish workflow fails before npm accepts the package, fix the cause on
`master`, rerun verification, replace the unpublished tag only after checking
remote state, and retry. If npm has accepted `0.1.0`, never move or recreate the
tag; make any correction in a new patch version.

## Security and credential handling

- Never print, save in the repository, or copy the npm token into logs.
- The bootstrap token is used only by the GitHub publish workflow.
- The token is revoked and the GitHub secret removed immediately after Trusted
  Publisher is configured and verified.
- Publishing remains restricted to GitHub-hosted runners with `id-token: write`,
  immutable action SHAs, exact tag/version validation, public access, and
  provenance.
- No force push, history rewrite, or existing release deletion is permitted.

## Verification and acceptance

Before the tag:

- `pnpm verify` passes from the exact `master` commit.
- `pnpm audit --prod` reports no known vulnerabilities.
- Documentation formatting and internal links are valid.
- GitHub metadata no longer exposes the obsolete prototype.

After the tag:

- The tag points to the verified `master` commit.
- The publish Actions run succeeds.
- npm serves `@baole-space/svg-motion@0.1.0` publicly with the intended nine
  tarball files and provenance.
- Root and `/react` imports resolve from a clean registry installation.
- GitHub Release `v0.1.0` is published with the expected notes.
- Trusted Publisher is configured, and neither the bootstrap token nor the
  `NPM_TOKEN` repository secret remains.
